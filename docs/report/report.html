Reading Heartbeats with a Quantum Reservoir

A matched comparison of a quantum and a classical reservoir on ECG beats from patients the models never saw in training

Joel Jobi

Quantum Healthcare Hackathon 2026 · National / Hybrid track · 26–28 October 2026

Code and records: github.com/joelynx/QML-Hackathon

The project on one page

Question
Does a quantum reservoir produce better features for flagging abnormal heartbeats in a patient it has never seen than a classical reservoir that matches it in input, feature count, readout and tuning budget?
Data
MIT-BIH Arrhythmia Database: 21 test patients, 47,129 scored beats. Second database for one confirmation run: MIT-BIH Supraventricular Arrhythmia Database (SVDB), 78 records, 184,286 beats.
Quantum model
A simulated 10-qubit quantum reservoir. Each beat is written into qubit rotations, the qubits interact, and 220 measured averages become the features.
Classical baseline
An echo state network (a classical reservoir) with the same input, the same 8 rhythm and amplitude features, the same 220-feature count, the same readout and the same tuning budget.
Amazon Braket
Noise simulation driven by the calibration data of two quantum processors; a check of the compiled circuits on Braket’s LocalSimulator; one task on a Rigetti Cepheus-1-108Q processor (48 beats, estimated USD 17.71).

Main result. The overall difference between the two reservoirs (macro-F1 +0.021, 95% confidence interval [−0.016, +0.062]; the score and the interval are explained in Section ) is inconclusive. On ventricular beats the quantum reservoir scored higher than the matched classical reservoir on the MIT-BIH test split (V-class F1 0.874 against 0.805) and raised about half as many false ventricular flags. That improvement has four qualifications: a classical mean-field model of the same circuit reaches the same V-class F1 (0.874); a gradient-boosting model reaches a higher one (0.943); simulated device noise lowers the quantum reservoir’s V-class F1 to 0.821; and on the second database no V-class gain appeared (difference −0.003, with an interval too wide to rule out a gain of the test-split size). The evidence therefore points to a feature map that a classical computer can evaluate cheaply, not to a benefit from quantum effects.

Design and checks

  • Patients are disjoint. No patient contributes beats to both training and testing. Two recordings of the standard split come from the same person; we removed the test one (Section ).
  • Rules fixed before tuning. The metric, the test split, the decision rule and four sub-questions were written down before any model was tuned. The author approved the evaluation before any model was scored on the test patients, and the evaluation program logs every test access (Section ).
  • One difference between the arms. The two arms share the input, the rhythm and amplitude features, the number of features, the readout and the tuning budget, and differ in the reservoir.
  • Controls. A mean-field model of the same circuit, the circuit without couplings, a rhythm-only model and a gradient-boosting model show which part of the pipeline produces the ventricular result (Section ).
  • Second database. The frozen models were scored once on SVDB under a criterion fixed in advance (Section ).
  • Hardware. The same circuit was checked on Braket’s simulator and run on a Rigetti processor (Section ).

Contributions

  • Our literature scan on 26 October 2026 (about 31 papers; not a systematic review) found no earlier quantum reservoir study on MIT-BIH that uses an inter-patient split and a matched classical reservoir.
  • A patient-relative input: each beat is compared with the median of the same patient’s previous 32 beats before it enters either reservoir.
  • The mean-field model of the same circuit used as an attribution test, to separate “a quantum-circuit feature map helps” from “quantum correlations help”.
  • An evaluation of one fixed circuit from exact simulation through shot noise, calibration-based noise and Braket’s simulator to a quantum processor, with five beats packed onto one chip per circuit.

The problem

What an ECG shows

Each heartbeat starts with an electrical impulse. An electrocardiogram (ECG) records the voltage that this impulse produces between electrodes on the skin, as a function of time. In a normal beat the impulse starts in the sinus node and spreads across the upper chambers (the atria), producing a small bump called the P wave. After a short delay in the atrioventricular (AV) node, it travels down a specialised fast-conducting pathway into the lower chambers (the ventricles), producing the tall, narrow spike called the QRS complex; finally the ventricles recover, producing the T wave. A lead is the voltage measured between a particular arrangement of electrodes; different leads view the same heartbeat from different directions. The time between two consecutive beats is the RR interval (from one R peak to the next); at 60 beats per minute it is 1 second.

An ectopic beat is a beat whose impulse starts somewhere other than the sinus node. Two kinds matter here:

  • Supraventricular ectopic beats (S) start early above the ventricles, in the atria or at the AV node. The impulse still reaches the ventricles through the normal fast pathway, so the QRS complex usually looks normal. What gives an S beat away is mostly its timing: it arrives earlier than expected, and its P wave may look different or be hidden.
  • Ventricular ectopic beats (V) start in the ventricular muscle itself. The impulse then spreads from muscle cell to muscle cell, which is much slower than the fast pathway, so the QRS complex becomes wide and its shape changes. V beats therefore differ from normal beats in both timing and shape.

This difference explains a pattern that runs through the results: shape-based features help much more with V beats than with S beats.

The clinical task

A Holter monitor records a patient’s ECG for a day or more, about 100,000 heartbeats per day. Software labels every beat, and a technician or cardiologist reviews the beats it flags as ectopic. There are two costs: a missed ectopic beat can hide an arrhythmia, and a false flag adds review work.

Why new patients are hard

Heartbeat shapes differ a lot between people, because of electrode placement, body shape and heart condition. If a model is trained and tested on beats of the same patients, it can recognise each patient’s own beats, and scores are high. The realistic setting is different: the model is trained on some patients and must work on a new patient with none of that patient’s labels. This is called the inter-patient setting, and performance drops in it, especially for S beats. In the reference inter-patient study, only 38.5% of the beats flagged as S really were S [3].

Many published quantum ECG studies split beats at random into training and test sets, so beats of the same patient land on both sides. Such studies measure recognition of patients the model has already seen. We split by patient throughout.

What earlier work led us to expect

In a benchmark of 12 quantum machine-learning models on 160 datasets, standard classical models performed better, and removing entanglement from the quantum models often did not hurt them [2]. When classical baselines are tuned as carefully as the quantum model, the quantum reservoir advantages studied by Pandey disappear [10] (we read the abstract only). A systematic review of quantum machine learning for digital health found that “performance differentials between quantum and classical algorithms show no consistent trend to support empirical quantum utility in digital health” [5]. For that reason the classical comparator here is matched to the quantum model, and the controls include a version of the circuit without entanglement.

The data

We use the MIT-BIH Arrhythmia Database [9], distributed by PhysioNet [11]: 48 half-hour recordings with two ECG leads from 47 people, sampled 360 times per second, with every beat annotated by cardiologists. The annotations are grouped into the five classes defined by the AAMI standard (a US standard for evaluating arrhythmia-detection software): N (normal beats, beats with a bundle-branch block, in which one of the two conduction branches into the ventricles is blocked and the QRS widens, and escape beats), S, V, F (fusion of a normal and a ventricular beat) and Q (paced or unclassifiable). Our task scores the three classes N, S and V; F and Q beats are predicted but left out of the scores. Recordings of patients with pacemakers are excluded, as is standard.

We use the standard de Chazal inter-patient split [3]: 22 training recordings (called DS1; 50,542 N, S and V beats) and 22 test recordings (DS2). One problem remained: recordings 201 (training) and 202 (test) come from the same person, as the database documentation states. We removed record 202 from the test set. The resulting test split, called ds2s, has 21 patients, 10.53 hours and 47,129 scored beats: 42,148 N, 1,781 S and 3,200 V.

The MIT-BIH Supraventricular Arrhythmia Database (SVDB; 78 half-hour records sampled 128 times per second, 184,286 beats) [4] was kept aside for a single confirmation run at the end (Section ).

The whole pipeline

  1. Cut out the beat. Take the ECG from 0.25 s before to 0.45 s after each annotated beat and reduce it to 40 numbers (Section ).
  2. Compare with the patient’s recent beats. Subtract the element-wise median of the same patient’s previous 32 beat windows.
  3. Feed a reservoir. Pass the 40 numbers, in 4 steps of 10, into a fixed dynamical system: 10 interacting qubits (quantum arm) or 55 interacting artificial neurons (classical arm).
  4. Read out 220 features. After each step, record 55 numbers that describe the reservoir’s state: 4 × 55 = 220.
  5. Add rhythm and amplitude. Append 8 numbers computed from the beat times and the beat’s size.
  6. Classify. A linear classifier (multinomial logistic regression) turns the 228 numbers into probabilities for N, S and V, and the most probable class is the prediction.

Only step 6 is fitted to training labels. It has 228 × 3 weights plus 3 offsets, 687 numbers in total. The reservoirs have a handful of settings (for example how strongly their parts interact), which are chosen by a search on the training patients and then fixed.

Building block 1: the input

The beat window

We use the lead called MLII (a modified limb lead II, recorded with electrodes placed on the chest), selected by its name (one recording stores it in its second channel, so selecting by channel number would have picked the wrong lead), at its native 360 samples per second. For each annotated beat at time ti, the signal from ti−0.25 s to ti+0.45 s (252 samples) is interpolated onto a fine grid and averaged into 40 equal bins. From the 40 values we subtract their median and divide by their standard deviation. This per-beat normalisation removes the beat’s local offset and amplitude, so the window describes shape only. No other filtering is applied.

Beat positions come from the database annotations; we do not build a beat detector. This is a deliberate limit of scope (Section ).

The patient-relative window

In a first experiment on the training patients (E001), adding the normalised window to the rhythm features lowered the cross-validated macro-F1 (the score defined in Section ) from 0.637 with rhythm features alone to 0.546. Our reading is that absolute shape is largely patient-specific, so a shape learned from one group of patients transfers poorly to another.

The reservoir input is therefore the window minus a template of the same patient’s recent beats:

ri=wi−median(wi−32,…,wi−1)

where wi is beat i’s 40-value window and the median is taken separately for each of the 40 positions. It uses only earlier beats and no labels, so it is available for a new patient. The element-wise median is not itself a recorded beat: at each of the 40 positions it is the middle value of the last 32 beats. Whenever more than half of those beats are normal, each of the 40 values lies within the range of the normal beats’ values at that position, because a median ignores a minority of unusual values. In the same experiment on the training patients this input recovered most of the loss: macro-F1 0.619 with the relative window and rhythm features (0.634 through an echo state network and 0.600 through the quantum reservoir, one untuned configuration each), still slightly below the rhythm features alone (anomaly A009), and it was fixed as the shared input of both reservoirs before any tuning.

The rhythm and amplitude block

Eight numbers are appended in every model. With RRpre the interval to the previous beat, RRpost the interval to the next beat, and RR10, RR50 the averages of the last 10 and 50 intervals, they are: RRpre, RRpost, RR10, the logarithms of the ratios RRpre/RR10, RRpost/RR10, RRpre/RRpost and RR10/RR50, and the logarithm of the beat’s peak-to-peak amplitude relative to the median amplitude of the previous 32 beats. An early ectopic beat has a short RRpre and often a long RRpost, so these ratios carry much of the S-beat information.

Using the next beat means the classifier must wait for it before deciding: it suits offline Holter analysis, not an instant alarm.

Building block 2: reservoir computing

A common picture of a reservoir is a pond: a stone thrown in produces ripples whose pattern depends, in a complicated way, on where and how it fell, and a simple rule applied to a photograph of the ripples can tell stones apart even though the rule knows nothing about water.

In precise terms, a reservoir is a fixed dynamical system with a state sk that is updated by each input uk through a fixed nonlinear rule sk=F(sk−1,uk). After each step some numbers describing the state are recorded as features, and only a simple model on top of those features (here a linear classifier) is trained. Because F is nonlinear and mixes the input steps together, the features contain products and other combinations of the inputs that a linear classifier could not form from the raw input. Because F is not trained, the model has few fitted parameters (687 here), which lowers the risk of fitting peculiarities of the 22 training patients.

Here the input steps u1,…,u4 are the four consecutive groups of 10 values of the patient-relative window, and 55 numbers are recorded after each step.

Building block 3: the classical reservoir (echo state network)

An echo state network [7] is a fixed, randomly connected network of artificial neurons. Its state is a vector h of 55 neuron values, and each input step updates it as

h←(1−a)h+atanh(ρWh+sWinuk+b)

  • W is a fixed sparse random 55 × 55 matrix (a fraction “density” of its entries are non-zero), rescaled so that its spectral radius is 1; ρ then sets the spectral radius actually used. An eigenvalue of a matrix is a factor by which the matrix stretches or shrinks some particular direction; the spectral radius is the largest such factor in magnitude, and it bounds how fast repeated multiplication by the matrix grows or shrinks a vector over many steps. A spectral radius below 1 is the usual rule of thumb for making the influence of old inputs fade.
  • Win is a fixed random matrix that feeds the 10 input values to the neurons, scaled by the input scale s; b is a fixed random bias vector scaled by the bias setting.
  • tanh squashes each neuron’s input into the range −1 to 1; this is the nonlinearity.
  • The leak a (between 0 and 1) sets how much of the old state is replaced at each step.

The 55 neuron values after each of the 4 steps give the 220 features. The ESN is the natural classical counterpart of a quantum reservoir: both are fixed dynamical systems with a trained linear readout. It is credited to Jaeger [7].

Tuning. Thirty configurations were drawn at random from a declared search space (size, spectral radius, leak, input scale, density, bias) and scored by cross-validation on the training patients only (Section ). The selected network (E002) has 55 neurons, spectral radius 0.68, leak 0.10, input scale 0.98, density 0.054 and bias 0.54.

Seeds. A seed is the starting number of a random-number generator; the same seed always gives the same random numbers. The random matrices of the echo state network, and in the quantum arm the random coupling disorder and the shot draws, come from seeds. Each final model was rebuilt with 5 different seeds and scored separately, and the results reported are means over the 5, so that no conclusion rests on one lucky draw.

Performance on the 21 test patients (mean of 5 seeds): macro-F1 0.7065. Per class (sensitivity / positive predictivity / F1, defined in Section ): N 0.907 / 0.985 / 0.944; S 0.595 / 0.269 / 0.370; V 0.953 / 0.697 / 0.805.

Grid check. The selected regularisation strength was the smallest value in its grid, so a better value might have lain outside it. With the grid extended to 10−5, the same configuration and value were selected and the predictions were byte-identical (E010). A separate verification run rebuilt this baseline and reproduced all five test prediction files byte for byte (V004; Section ).

Building block 4: the quantum reservoir

This section builds up the quantum model from its smallest part. The grey boxes give the exact definitions.

One qubit

A classical bit is 0 or 1. A qubit is described by two complex numbers α and β with |α|2+|β|2=1, written |ψ⟩=α|0⟩+β|1⟩. When the qubit is measured, the result is 0 with probability |α|2 and 1 with probability |β|2, and the measurement ends the computation for that qubit. A single measurement therefore gives one random bit, not the numbers α and β.

The quantity we use as a feature is the average value of the measurement if we count 0 as +1 and 1 as −1. It is written ⟨Z⟩:

⟨Z⟩=P(0)−P(1)=|α|2−|β|2

It is +1 if the qubit always gives 0, −1 if it always gives 1, and 0 if both are equally likely.

In more detail: the Bloch sphere. Up to an overall phase that has no measurable effect, a single-qubit state can be drawn as an arrow of length 1 from the centre of a sphere (the Bloch vector). The arrow’s vertical component is exactly ⟨Z⟩: the north pole is |0⟩ (⟨Z⟩=+1), the south pole is |1⟩, and points on the equator have ⟨Z⟩=0. Single-qubit gates are rotations of this arrow.

The three gates

A quantum gate changes the state in a fixed, reversible way. The circuit uses three:

  • RY(θ) rotates the Bloch arrow by angle θ about the Y axis. Starting from |0⟩, it gives cos(θ/2)|0⟩+sin(θ/2)|1⟩, so ⟨Z⟩=cosθ. We use it to write data: the angle is proportional to an input value.
  • RX(h) rotates the arrow by angle h about the X axis. Applied to every qubit, it plays the role of a “transverse field” in physics models.
  • ZZ coupling exp(−iJZqZr) acts on two qubits q and r. It multiplies each part of the state by a phase e−iJ if the two bits are equal and e+iJ if they differ. A phase factor eiφ is a complex number of magnitude 1, so on its own it changes no measurement probability (probabilities are squared magnitudes). What changes is the relative phase between the parts of the state; the following RX rotations mix the parts together, so the relative phases then change the probabilities, and the two qubits’ outcomes become correlated. J sets the coupling strength.

Ten qubits: correlations and entanglement

Ten qubits have 210=1,024 possible measurement outcomes (bit strings), and their joint state is a list of 1,024 complex numbers (amplitudes), one per outcome; the probability of an outcome is the squared magnitude of its amplitude. Besides each qubit’s ⟨Zq⟩, we record for every pair of qubits the average of the product of their ±1 values:

⟨ZqZr⟩=P(bits q and r equal)−P(bits differ)

Ten qubits give 10 single averages and 45 pairs, so 55 numbers per measurement.

If each qubit has its own independent state (a product state), the pair averages carry no new information: ⟨ZqZr⟩=⟨Zq⟩⟨Zr⟩, just as for two independent coins. A state that cannot be written as a product of single-qubit states is called entangled. Entanglement is what makes the 1,024 amplitudes necessary; a product state of 10 qubits is described by 10 Bloch arrows, 30 numbers. The ZZ couplings are the only gates in our circuit that can create entanglement. A single ZZ gate is most entangling at J=π/4≈0.79 and creates no entanglement at J=0; for small J, below about 0.79, a stronger coupling lets the state move further from a product state.

The circuit

The ten qubits start in |0…0⟩ (every ⟨Zq⟩=1). For each input step k=1,…,4:

  1. Write the data. Qubit q is rotated by RY(s·xk,q), where xk,q is the q-th of the step’s 10 values and s is the input scale. Because the qubits already carry the earlier steps, writing new data into them is called data re-uploading.
  2. Let the qubits interact. Twice: apply ZZ couplings between neighbours on a ring (qubit 0–1, 1–2, …, 9–0), each with its own strength Jqr=J(1+duqr), where uqr is a fixed random number between −1 and 1 and d is the disorder setting; then RX(h) on every qubit.
  3. Measure. Estimate the 10 values ⟨Zq⟩ and the 45 values ⟨ZqZr⟩ from 1,024 repetitions (Section ).

Measuring destroys the state, so “measure after step k” really means running a separate circuit that contains steps 1 to k and measuring at its end. Each beat therefore needs 4 circuits of 10 qubits, and gives 4 × 55 = 220 features, the same count as the classical network.

Shots: estimating averages from repeated runs

One run of a circuit (one shot) gives one 10-bit outcome. To estimate ⟨Zq⟩, the circuit is run N times and the ±1 values are averaged. The estimate is random. Its standard error, the typical size of the gap between the estimate and the true value, is (1−⟨Z⟩2)/N, at most 1/N. With N=1,024 that is at most 1/32 ≈ 0.031, and four times as many shots halve it. Real devices can only produce such estimates, so the headline quantum model uses 1,024 simulated shots rather than the exact averages.

How the circuit is simulated

We wrote a statevector simulator that runs on a graphics card (GPU) with PyTorch: it stores the 1,024 amplitudes of each beat’s state, applies every gate as the corresponding exact matrix operation, computes the 1,024 outcome probabilities at the end, and draws 1,024 shots from them. It agrees with an independent implementation that builds the full 1,024 × 1,024 matrices to within 4×10−7 (E001).

Each beat draws its shots from its own random-number stream, identified by the beat and the seed, and the arithmetic is done in double precision. A beat’s features therefore do not depend on which other beats were simulated in the same batch. Together with double-precision arithmetic in the classical network and the readout (anomaly A011), this makes every headline prediction file reproducible byte for byte.

The selected settings

The quantum reservoir got the same tuning procedure and budget as the classical one: 30 random configurations of input scale, coupling J, field h, depth (layers per step), ring or chain, and disorder, scored on the training patients only. The selected configuration (E003) has input scale 0.317, J = 0.106, h = 0.159, depth 2, a ring and disorder 0.42.

The selected coupling is weak: J = 0.106 lies near the bottom of the search range (0.1 to 1.5), well inside the small-J regime. By Section , weak couplings keep the state close to a product state, which is why the mean-field control of Section is a direct test of whether entanglement matters here.

Building block 5: the readout and the tuning procedure

Both arms end in the same classifier.

  1. Standardise. Each of the 228 features has the training-set mean subtracted and is divided by its training-set standard deviation, so that all features are on comparable scales.
  2. Score each class. For each class c (N, S, V), a weighted sum zc=wc·x+bc of the standardised features is computed.
  3. Turn scores into probabilities with the softmax function pc=ezc/∑c′ezc′; the prediction is the class with the largest probability.

Fitting. The weights are chosen to minimise the average of −logptrue class over the training beats (the cross-entropy, small when the true class gets high probability), plus a penalty λ∑w2 on the squared weights that discourages extreme weights (L2 regularisation). The penalty strength λ is chosen from {0.001, 0.01, 0.1, 1}. S and V beats are rare (3.8% and 6.8% of the test beats), so an unweighted fit would favour N. Each beat is therefore weighted by n/(3nc), where n is the number of training beats and nc the number in its class, so that each class contributes equally to the fit (“class-balanced”).

Tuning by patient-grouped cross-validation. The 22 training recordings are split into 5 fixed groups. For each candidate configuration, the classifier is fitted on four groups and used to predict the fifth, in turn, so every training beat gets a prediction from a model that never saw its patient. The configuration with the best macro-F1 on these out-of-fold predictions is selected. Both arms used 30 randomly drawn configurations, the same procedure and the same seed scheme, and the test patients played no part.

How the comparison was made fair

Measuring performance: sensitivity, positive predictivity, F1

For one class, say V, every beat falls into one of four groups: true positives (TP: V beats predicted V), false positives (FP: other beats predicted V), false negatives (FN: V beats predicted as something else), and the rest. Then

  • sensitivity = TP / (TP + FN), the fraction of V beats found;
  • positive predictivity (precision) = TP / (TP + FP), the fraction of V predictions that are correct;
  • F1 = 2 · sensitivity · precision / (sensitivity + precision), their harmonic mean, which is high only if both are high.

Example: the quantum arm’s V sensitivity is 0.949 and its V precision 0.811, so its V F1 is 2 × 0.949 × 0.811 / (0.949 + 0.811) = 0.874. For the classical arm, 0.953 and 0.697 give 0.805.

Macro-F1 is the plain average of the N, S and V F1 scores. Because 89% of test beats are normal, accuracy alone would reward a model that ignores the rare classes. A model that calls every beat normal gets N F1 0.944 but S and V F1 of zero, so its macro-F1 is 0.315; in macro-F1 the rare classes count as much as the common one.

Uncertainty: the patient bootstrap

Beats of the same patient resemble each other, so the 47,129 test beats are not 47,129 independent observations; the number of independent units is closer to the 21 patients. To estimate how much the difference between two models could change with a different set of patients, we use a bootstrap: draw 21 recordings at random with replacement from the 21 (so some appear twice and some not at all), use the same draw for both models, also resample the 5 seeds within each model, recompute the difference in macro-F1, and repeat 8,000 times. The range that contains the middle 95% of the 8,000 differences is the 95% confidence interval. If it excludes zero, a difference of that sign is unlikely to come from the particular choice of patients alone. The intervals are conditional on the fixed training set and the selected configurations; they do not cover the uncertainty of training on other patients.

Rules fixed in advance

The decision rule, the sub-questions and the access rules were written into the evaluation specification (EVAL.md) before tuning began. Tuning ran under that draft, and both arms’ test predictions were written but not scored; the author then approved the specification unchanged before any model was scored on the test patients. Two fixed reference rules, which involve no training (for example “call every beat normal”), were scored on the test split earlier while the evaluation was being built; they do not count towards the limit below.

  • Decision rule for the main comparison. Favorable only if the macro-F1 difference is at least +0.02 (a size we judged worth reporting), its 95% interval excludes zero, and it stays positive when record 232 is left out (this one patient holds most of the S beats; Section ). Unfavorable if the interval lies wholly below zero. Otherwise no detectable change, which means the evidence is insufficient, not that the models are equal.
  • Four sub-questions (the “slice family”): S-class F1, V-class F1, and macro-F1 after refitting both readouts on only 5 and on only 11 training patients. Asking four questions instead of one raises the chance of a false positive, so each is tested at the 98.75% level instead of 95%: with four tests each allowed a 1.25% error rate, the chance of any false positive is at most 4 × 1.25% = 5% (the Bonferroni correction).
  • Access control. Every scoring on the test split is logged automatically with a fingerprint (hash) of every prediction file; at most 15 scorings were allowed without the author’s further approval; and the first scoring of any trained model on the test split had to be the pre-registered main comparison. 13 of the 15 were used. The evaluation program enforces these rules, and it runs the second database through a dry run with placeholder labels before the real access is logged. The evaluation code has 43 automated tests.

The lookahead check

A classifier for beat i may use the signal up to a boundary: the next beat, or 1 s after beat i if that is later. To check that no feature uses anything beyond it, the check replaces all of the signal after the boundary with different values, recomputes the whole pipeline, and requires the prediction for beat i to stay exactly the same. Every reservoir model passed on 731 training beats with 0 violations.

Separate verification

Five separate reviews (V001–V005) checked the work. V001–V003 reviewed the evaluation before any model was scored; V004 and V005 checked the results. These reviews were part of the project’s own workflow, not external peer review. V004 rebuilt the classical baseline and reproduced its five test prediction files byte for byte. V005 checked the external confirmation, the additional experiments and the claims in the README. It also rebuilt the 10 headline prediction files and the headline table from a fresh environment and a fresh data download, byte for byte, in 27.3 minutes. The full reports are in VERIFICATIONS.md.

The ventricular result

Both arms find almost the same number of V beats (3,036 for the quantum arm against 3,050 per seed). The difference is in false V flags, which fall from 1,324 to 709 per seed. Most of the removed false flags are normal beats in patients with few or no V beats (records 117, 222, 105, 111 and 212) and S beats in record 232. V precision therefore rises from 0.697 to 0.811 at nearly the same V sensitivity (0.953 against 0.949). Among the 9 test patients with at least 10 V beats, the quantum arm has the higher V F1 in 5.

The S class and record 232

Record 232 holds 1,381 of the 1,781 S beats in the test split (77.5%), so S scores on this split largely measure one patient. The quantum arm finds 310 fewer S beats per seed than the classical arm, 288 of them in record 232. Leaving out any single record keeps the main difference positive (from +0.011 without record 213 to +0.046 without record 232), but this does not change the pre-registered interval.

Where the ventricular result comes from: the controls

The mean-field model

The mean-field model runs the same gates with the same settings, but forbids entanglement: every qubit keeps its own Bloch arrow throughout (Section ). The single-qubit gates rotate each arrow exactly as before. Each ZZ coupling, which needs the joint state, is replaced by a rotation of qubit q’s arrow about the Z axis by the angle 2Jqr⟨Zr⟩, and of qubit r’s arrow by 2Jqr⟨Zq⟩, as if each neighbour were replaced by its average. Pair averages are then products of single averages, and the same 1,024-shot sampling is applied. The model needs 30 numbers instead of 1,024 amplitudes, and its cost grows linearly with the number of qubits instead of doubling with each added qubit. This kind of control is used in the quantum reservoir literature [8]. With the couplings switched off (J = 0) it agrees with the full simulation to within 3.5×10−6, as it must, since a circuit without couplings never leaves a product state.

If the quantum arm’s V-class result depended on entanglement, the mean-field model would score lower. The results:

The mean-field model matches the quantum reservoir within intervals that include zero, both overall and on V beats. Removing the couplings entirely lowers V-class F1 by 0.063 (and raises S-class F1). The 8 rhythm and amplitude features alone reach a macro-F1 of 0.700, close to the classical reservoir’s 0.707. The couplings therefore affect the result, and a classical model of their average effect reproduces it. An interval that includes zero does not prove that two models are equal, so the conclusion is limited to this: the benchmark detected no added benefit of the full quantum model over the mean-field model.

In more detail: how close is the state to a product state? For a product state every pair average equals the product of the two single averages. On the 48 beats of the hardware run (Section ), using the exact simulation of the selected circuit, the pair averages have an average size of 0.606, while their average departure from the product |⟨ZqZr⟩−⟨Zq⟩⟨Zr⟩| is 0.013. The largest single departure is 0.45, so the state is not a product state everywhere, but on average the correlators add little beyond the single-qubit averages. A zero departure is necessary for a product state but does not by itself prove one; the numbers show consistency with the mean-field result, not a proof (scripts/report_numbers.py).

A stronger classical model

The matched echo state network is a controlled comparator, not necessarily the strongest classical model. After the test results were known, we tuned a gradient-boosting classifier on the same inputs (the 40-value patient-relative window and the 8 rhythm and amplitude features) with its own budget of 30 configurations on the training patients (E016). A decision tree classifies a beat by a sequence of yes/no questions about its features (for example “is the interval to the previous beat shorter than a threshold?”), each answer leading to the next question until a final class score is reached. Gradient boosting builds a sequence of such trees, each one fitted to correct the errors of the trees before it, and adds their scores. This comparison was chosen after the results were seen, so it is secondary and descriptive.

Overall there was no detectable difference from either reservoir, a result that rests on record 232: the boosted trees rarely predict S (655 of 47,523 test beats, against 2,585 for the quantum arm) and so miss the S beats of record 232. Their V-class F1 is 0.943, higher than the quantum arm’s 0.874 (difference −0.068 [−0.159, −0.031]) and the classical reservoir’s 0.805. Without record 232 they lead the quantum arm by 0.087 in macro-F1.

Similarity of the feature maps

We also compared the feature maps directly on the training patients, without any labels (E017).

Linear CKA (centred kernel alignment) asks whether two feature sets arrange the beats the same way. For each feature set, compute the similarity (dot product of the standardised features) of every pair of beats; after centring both tables, CKA is their cosine similarity, a correlation-like score between 0 and 1. It is 1 when one feature set is a rotation and a uniform rescaling of the other. Quantum vs mean-field: 0.986. For scale: the quantum map against itself with new shots, 0.992; against a version with another random reservoir seed, 0.989; quantum vs classical reservoir, 0.525. The mean-field map is therefore about as close to the quantum map as a rerun of the quantum map is.

The geometric difference of Huang et al. [6] compares a quantum kernel (beat-similarity table) with a classical one. Huang et al. show that when it is small, a classical model using the classical kernel can predict as well as a model using the quantum kernel from a comparable amount of training data. Measured at the smallest regularisation used, it is 9.6 between the mean-field and quantum maps, comparable to 10.5 between the quantum map and a shot-noise rerun of itself, and 35 for the classical reservoir. These values are descriptive, because none of the pairs meets the paper’s rule for choosing the regularisation; only their sizes relative to each other are interpreted here.

Additional experiments

These experiments were written down before they ran and reuse the selected quantum settings, but they were chosen after the main results had been seen. Their test-split comparisons are therefore secondary and descriptive and cannot change the main result.

Number of shots

Replacing the 1,024-shot estimates by exact averages (E012) changes test-split macro-F1 by +0.0005 [−0.0058, +0.0081]: at 1,024 shots, shot noise has no measurable effect. On the training patients (E013), macro-F1 is flat from 1,024 shots upward and lower at 64 shots (0.648 against 0.667). The average feature error halves with every fourfold increase in shots (0.0675, 0.0337, 0.0169 and 0.0084 for 64, 256, 1,024 and 4,096 shots), as the formula in Section predicts.

Number of qubits

On the training patients (E014), 6 qubits scored 0.680, 8 qubits 0.667 and 12 qubits 0.6635, against 0.667 for 10. Ten qubits with only the 10 single averages (no pair averages) scored 0.678. On the test split, 6 qubits against 10 gave +0.0078 [−0.0055, +0.0188]. More qubits did not help and the pair averages added little, consistent with the mean-field result. Changing the qubit count also changes how finely each 10-value input step is resampled, so the two effects cannot be separated.

Device noise

Real quantum processors make errors. We simulated two kinds (E015), at rates taken from the calibration data that Amazon Braket reports for two processors (Section ):

  • Gate errors, modelled as depolarising noise: after each gate, with a small probability given by the device’s error rate, a random Pauli error is applied to the qubits the gate acted on: X swaps 0 and 1, Z flips the sign of the |1⟩ part, and Y does both.
  • Readout errors: each measured bit is reported wrongly with the device’s readout error probability.

Because the errors are random, the simulation runs each circuit 32 times with different randomly inserted errors (32 “trajectories”) and draws 32 shots from each, 1,024 shots in total. The readout classifier is retrained on the noisy features. Idle decay of the qubits, crosstalk between them and the routing of qubits on a real chip are not modelled.

Why noise shrinks the features. A readout error with probability ε turns +1 into −1 and vice versa, so it multiplies every ⟨Z⟩ by (1−2ε) and, with independent errors on the two bits, every pair average by (1−2ε)2. At Rigetti’s readout error of 0.031 these factors are 0.938 and about 0.88. Depolarising errors likewise pull averages towards zero, and they accumulate with every gate.

Result. We had predicted that noise would make the model behave like the circuit without couplings. That prediction failed. On the training patients, the noisy V-class F1 (0.699 at Rigetti’s rates, 0.717 at IQM’s) fell below both the noiseless circuit (0.742) and the circuit without couplings (0.756). On the test split, at Rigetti’s rates, V-class F1 fell from 0.874 to 0.821, so most of the V-class margin over the classical reservoir (0.805; an unpaired, descriptive comparison) does not survive device noise in simulation. Because idle decay, crosstalk and routing are missing, real hardware is expected to be worse.

Amazon Braket: from simulator to a quantum processor

What Braket is, and what a device can run

Amazon Braket is a cloud service from Amazon Web Services that runs quantum circuits on simulators and on processors built by several companies, and charges per task and per shot [1]. Each processor can execute only its own small set of native gates on specific physical qubits; for Rigetti these include single-qubit rotations and the two-qubit CZ gate, which flips the sign of the state when both qubits are 1. Our ZZ coupling is not native, so we compiled each one into 2 CZ gates surrounded by single-qubit rotations. A 4-step snapshot circuit with 2 layers of 10 ring couplings per step therefore contains 4 × 2 × 10 × 2 = 160 CZ gates. We submitted the compiled circuits as verbatim programs, which the device runs exactly as written on the qubits we chose, without re-compiling them.

Calibration data for the noise simulation

Braket publishes each device’s recent calibration measurements at no cost. Fetched on 28 October 2026, the chip-wide medians were: Rigetti Cepheus-1-108Q, single-qubit gate error 0.0030, CZ error 0.0117, readout error 0.031; IQM Garnet, 0.0006, 0.0045, and readout errors 0.010 (0 read as 1) and 0.027 (1 read as 0). These rates drove the noise simulation of Section , on the training beats for both devices and on the test beats for Rigetti.

Checks on Braket’s LocalSimulator

The LocalSimulator is Braket’s free simulator that runs on one’s own computer and accepts the same programs as the devices. Before any paid task we ran our compiled programs on it:

  • Correctness. For all four snapshots of each of 4 test beats, on both devices’ gate sets (up to 160 CZ and 995 single-qubit gates per beat snapshot on one 10-qubit ring), the LocalSimulator’s exact results agree with our own simulator to within 3.5×10−6.
  • Packing. Two beats placed on separate 10-qubit rings of the same chip give the same results as each beat alone, to within 3.1×10−6.
  • Bit order. Devices report measured bits in a fixed order, and reading them in the wrong order would silently scramble the features. With the correct order, 1,024-shot results differ from the exact values by 0.015–0.033 on average; with a fully reversed order, by 0.10–0.22 on single-ring circuits and by 0.038 and 0.18 on the two packed circuits.
  • Analysis path. Each 10-qubit ring of the packed 24-beat Rigetti plan was run separately on the LocalSimulator (96 runs, 1,024 shots), written in the hardware result format and processed by the same analysis code used for the hardware. The features match the exact simulation with mean absolute difference 0.018 and correlation 0.997, the size expected from shot noise alone. The batch submission format (a “program set”) was checked separately with two programs.

Spending controls

The submission script accepts only two devices (Rigetti Cepheus-1-108Q and IQM Garnet), at most 1,024 shots per circuit, and only with an approval file, written after the author approved, naming the device, the number of tasks and a spending cap. It records each cost estimate in a ledger before submitting, and refuses a task if the estimated running total would exceed the cap. The estimates use the published prices; the actual bill is to be checked in AWS Billing. The first submission was refused by AWS before any task was created, because the account lacked a required Braket service role; nothing was charged. The role was created with the author’s approval and the same job was resubmitted.

One task on the Rigetti processor

Each beat needs 4 circuits of 10 qubits, and Rigetti Cepheus-1-108Q had 107 qubits available when we fetched its description. Beat packing places five beats side by side on separate 10-qubit rings of the chip in one circuit, so 48 beats × 4 snapshots needed 40 circuits instead of 192. One task ran 40 circuits × 1,024 shots at an estimated USD 17.71 (USD 0.30 per task plus USD 0.000425 per shot: 0.30 + 40 × 1,024 × 0.000425), approved by the author with a USD 18 cap within the overall USD 35 limit. All 48 beats completed. The beats were drawn from the test split without looking at their labels: 16 for each class predicted by the simulation.

What a full day would cost

This is arithmetic, not a measurement. Four circuits × 1,024 shots is 4,096 shots per beat. One Holter day of about 100,000 beats would need about 410 million shots, about USD 174,000 at Rigetti’s on-demand price of USD 0.000425 per shot [1] (without beat packing, which could cut the shot count up to fivefold; task fees excluded). A 10-qubit state has only 1,024 amplitudes and is easy to simulate on an ordinary computer, so this study makes no claim of computational advantage.

Limitations

  • No quantum advantage was found. A classical mean-field model of the same circuit reaches nearly the same performance; the result concerns a quantum-circuit feature map, not a speed-up or an accuracy gain from entanglement.
  • The main comparison is inconclusive. One of four sub-questions is favorable; that does not change the main result.
  • Stronger classical models exist. Gradient boosting has a higher V-class F1 than both reservoirs (post-hoc comparison).
  • Not confirmed on the second database.
  • A trade-off. Fewer flags come with 36 more missed ectopic beats per hour; review time was not measured.
  • Few test patients. 21 test patients, and one of them (record 232) holds 77.5% of the test S beats, so intervals are wide.
  • Scope. Annotated beat positions are used (no beat detector); the classifier waits for the next beat, so it suits offline use; MIT-BIH was deliberately enriched with uncommon arrhythmias, so its per-hour rates are not clinical rates.
  • Simulation. All scored results are simulated; the noise model omits idle decay, crosstalk and routing; the hardware run is a small diagnostic without labels.
  • Post-hoc experiments. The additional experiments were chosen after the main results were seen.
  • Conditional intervals. The intervals cover test patients and seeds for the fixed training set and selected configurations, not training on other patients.

Engineering log

The problems below were found during the project and changed what was built or reported.

The standard split shares a patient (A004)

Symptom
The headers of recordings 201 (training) and 202 (test) describe the same 68-year-old man on the same medications.
Diagnosis
The database documentation confirms that both come from the same subject. The widely used split separates recordings, not people.
Fix
The primary test split drops record 202 (21 patients). The published 22-record split is kept only as a secondary split for comparison with the literature.

Absolute beat shape transferred poorly across patients (E001, A009)

Symptom
On held-out training patients, adding the beat window to the rhythm features lowered macro-F1 from 0.637 to 0.546.
Diagnosis
Our interpretation: absolute shape is largely patient-specific, while the difference from the patient’s typical recent beat is less so. The experiment supports this for these data; it does not prove it in general.
Fix
The patient-relative window, fixed as the shared reservoir input before tuning, and a rhythm-only control (E006) reported next to the main comparison and the controls.

Predictions that depended on batch size (A011)

Symptom
The first lookahead check of the classical baseline flagged two beats whose probabilities changed by about 10−7 when unrelated later beats were removed.
Diagnosis
Single-precision matrix products round differently for different batch shapes. The changes were of the size of single-precision rounding, and they disappeared with double precision, which identifies rounding as the cause in this case.
Fix
Double precision for the network update and the readout (the shot sampler had already been fixed the same way). The check then passed with 0 violations, and retuning in double precision selected the same configurations.

A baseline setting at the edge of its grid (A010)

Symptom
The classical baseline selected the smallest regularisation strength in its grid.
Diagnosis
A better value could have lain outside the grid, which would have handicapped the baseline.
Fix
The grid was extended to 10−5 (E010, E011). Both arms selected the same settings and the predictions were byte-identical, so the grid edge did not handicap the baseline.

A test of the access guard opened a locked label file (26 October, 17:45)

Symptom
Before any model existed, a path bug made a test of the confirmation guard open the real SVDB label file.
Diagnosis
The run stopped on a beat-identifier check before any score was computed; no label values or scores were displayed or stored.
Fix
The bug was fixed and the test now asserts that the real file is never opened. A separate review (V002) judged that SVDB remained usable as a confirmation set. Details are in the access log of EVAL.md.

Reproducing the work

The code runs with Python 3.12 (tested on Windows 11; one CUDA graphics card recommended). The raw data are downloaded from PhysioNet’s open-data mirror, and every file is checked against PhysioNet’s published SHA-256 checksums. To regenerate the 10 headline prediction files without a new test-split scoring, follow the “audit mode” procedure in Section 9 of the README:

  1. In a new, empty directory, copy src/, tests/, scripts/, pyproject.toml and requirements-lock.txt from the repository, plus two reference files: runs/full_eval_log.jsonl and runs/E003/compare_ds2s_headline_EV2.json.
  2. Create the environment there:
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements-lock.txt
.venv/Scripts/python -m pip install -e .
  1. Run the check, which downloads the data, rebuilds the features, retunes and refits both arms, and compares the 10 prediction files with the logged hashes:
.venv/Scripts/python scripts/reproduce.py --check

The check refuses to run in a directory that already contains tuning results, so it cannot overwrite the repository’s records. Our own run took 26 minutes (without the data download); the verification run, from a fresh environment with a fresh data download, took 27.3 minutes. Both matched byte for byte. docs/EVIDENCE.md maps each number in the README to its experiment record and output file.
